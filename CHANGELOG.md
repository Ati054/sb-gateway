# Changelog

## 1.6.33

Полный набор пользовательских изменений относительно публичной 1.6.27
(image revision `20939124299b4ed78e50a915eae5953c234ce231`).
Релизы 1.6.31 и 1.6.32 сняты и не переиздаются.

- Исправлены подтверждённые race detector гонки selector cache, раннего отказа
  XHTTP и публикации обновлённых TLS/OCSP-сертификатов; добавлены регрессионные тесты.
- Сохранение/reset/CRUD черновика при занятой конфигурации сразу возвращают
  явный HTTP 409 без изменения данных, вместо ожидания и поздней записи после 504.

- Серверный Xray-core обновлён с 26.9.9 до 26.9.30 (upstream prerelease),
  exact pin `b26a91de4f3294e26a0ad0a970b81a386a41f789`.
  Перенесены локальные patches Vision/REALITY, failure signal и bounded
  transport retirement с учётом нового FinalMask dial path.
- Динамические группы узлов: одна или все подписки, страна, протокол,
  включения по имени/emoji и исключения целых слов. Состав пересчитывается
  после обновления подписок; доступны preview состава и исходный порядок узлов.
- Пользовательские правила доменов, IP/CIDR и TCP/UDP-портов/диапазонов
  направляют трафик через WAN или VLESS. Для доменов/IP доступны необязательные
  HTTP/TLS/QUIC-фильтры; правила учитываются и в совместимых клиентских профилях.
- Региональный каталог сервисов расширен карточками Китая и Ирана;
  обработка GeoSite учитывает поддерживаемые формы правил. Новые выбранные
  карточки обновляются перед Apply; неподдерживаемые GeoSite labels не ломают
  DNS-исключения RouterOS при отказе контейнера.
- Необязательные GeoIP country routes с ограничением размера: ручное/ежесуточное
  обновление и горячая активация без перезапуска Xray. Откат обновления
  восстанавливает прежние активные GeoIP-правила.
- Исправлены преждевременные откаты Apply с крупным GeoIP: readiness ждёт
  завершённую валидацию текущего Xray, а watchdog не компилирует ту же базу
  повторно. Бюджеты запуска и восстановления учитывают крупные правила.
- Фоновый GeoIP refresh отложен на весь Apply/rollback; неизменные правила
  не загружаются повторно после изменения посторонней monitor-настройки.
- Горячее изменение политики сохраняет активный selector. После планового
  перезапуска и runtime-only Apply восстанавливается managed traffic gate;
  watchdog не вмешивается в незавершённый RouterOS rollback.
- URLTest сохраняет историю при ошибке чтения/перезапуске и обновляет поколение
  выбранного узла после refresh подписки без потери истории остальных узлов.
- Плановые переключения временно обходят нестабильные узлы; подтверждённый
  отказ учитывается отдельно от обычного замера. После общего сбоя WAN/DNS
  активный узел подтверждается заново, без переключения по старой ошибке.
- Аварийный поиск рабочего резерва не прерывается фоновой проверкой другого
  листа; устаревшие probe results отклоняются после смены runtime generation.
- Зависшее установление XHTTP/TCP ограничено тайм-аутом, а открытые соединения
  сохраняются при переключении и удалении прежнего обработчика.
- Скрипты RouterOS автоматически согласуются с установленной версией контейнера.
  Журналы «Маршруты» и Control plane разделены; обычные probe-команды не
  засоряют журнал RouterOS, предупреждение о нестабильности требует устойчивого отказа.
- Редактор листов, групп и пользовательских правил выровнен на desktop/mobile;
  статус обновления подписки различает получение узлов и их активацию.
- Watchdog проверяет реальные nft hooks/TPROXY/reject по структурированному JSON,
  исключая ложный отказ из-за канонического форматирования `nft list`.
- Неподдерживаемый публичный IP-транзит явно отклоняется без routing loop и
  скрытого WAN bypass. VLESS/Xray переносит TCP/UDP, не публичный ICMP/ping.
- Routing reload patch сохраняет selector override и сериализует reload/override;
  build запускает поведенческие regressions, а не только compile check.
  Экспортируемый Reverse bridge сохраняет pin 26.7.28; RAW/XHTTP/gRPC
  совместимость с новым серверным ядром подтверждена напрямую.
