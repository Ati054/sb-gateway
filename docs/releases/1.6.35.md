# SB Gateway 1.6.35

Изменения относительно публичной 1.6.34.

## URLTest и Приоритет

- Подтверждённая просадка собственной скорости активного узла запускает поиск стабильного резерва. В URLTest пороги просадки и выигрыша независимы; в приоритетном режиме есть только порог просадки, 0 отключает скоростной выход.
- URLTest сравнивает резервы свежими парами до переключения, избегая промежуточного более медленного узла. В приоритетном режиме сохраняется порядок очереди; чужой прирост скорости не меняет маршрут сам по себе.
- Недавно просевшие узлы проходят защиту от планового возврата; одиночный всплеск скорости её не отменяет. Аварийный поиск работающего маршрута не задерживается этой защитой.
- Скоростные замеры связаны с имеющимися интервалами качества: стандартно активный узел каждые 3 минуты, рабочие резервы каждые 15 минут. Нового поля интервала нет; подтверждения, общие лимиты и медленный обход остального набора могут увеличивать ожидание.
- Авто использует 5 одновременных HTTPS-проверок и рабочий пул из 5 узлов. Листы делят общий бюджет уникальных серверов и не дублируют свежие проверки пересекающихся узлов. Сохранённые настройки не перезаписываются; скоростные скачивания выполняются последовательно.
- Ошибки подготовки служебного селектора Xray не считаются отказом VPN-узла. Параллельные фоновые API-команды ограничены; прерванные проверки повторяются без ложного ухудшения здоровья маршрута.

## URLTest And Priority

- Confirmed degradation against the active node's own speed baseline starts a stable-reserve investigation. URLTest has independent drop/gain thresholds; priority mode exposes only the drop threshold, with 0 disabling speed-driven exits.
- URLTest freshly compares reserves before switching, avoiding an intermediate slower choice. Priority retains queue order and does not switch merely because a reserve gains speed.
- Recently degraded nodes require spaced recovery confirmations before planned return. One speed spike does not clear protection; emergency recovery still searches for a working route.
- Routine speed follows existing quality intervals: normally 3 minutes for the active node and 15 minutes for working reserves. No extra interval field is added. Confirmation work, shared budgets and slower inventory exploration can delay measurements.
- Auto uses 5 concurrent HTTPS checks and a 5-node working pool. Lists share a unique-endpoint budget and reuse fresh overlapping results. Saved limits are preserved; speed downloads remain sequential.
- Local Xray selector preparation errors do not penalize VPN node health. Concurrent background API commands are bounded, and interrupted work is retried.
