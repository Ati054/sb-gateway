# SB Gateway 1.6.20

## Русский

### Описание

Версия 1.6.20 закрывает два сценария восстановления конфигурации. Чистая
установка восстанавливается после прерывания самого первого Apply, а ручной
откат подчиняется тем же ограничениям конкурентного доступа, что и обычный
Apply.

### Изменения

- Перед первым Apply система сохраняет отдельную безопасную recovery
  generation. Если процесс завершится до создания `active.json`, следующий
  запуск восстановит runtime и RouterOS, проверит результат и разрешит
  повторить Apply. Неподтверждённый candidate не становится активным.
- Ручной откат использует общий mutation barrier. Он не запускается во время
  обновления контейнера, probation, восстановления, активации подписки или
  другого незавершённого Apply и не меняет чужой журнал операции.
- Обновление с 1.6.19 сохраняет активную конфигурацию, секреты, журналы
  качества узлов и пользовательские настройки.

### Установка и обновление

Для чистой установки используйте `sb-gateway-1.6.20-routeros-bundle.zip` и
[инструкцию](../INSTALL-RU.md).

Для обновления работающей установки загрузите
`sb-gateway-1.6.20-linux-arm64.tar` в разделе
**Эксплуатация → Обновление контейнера**. Панель проверит архитектуру, версию и
SHA-256 до остановки текущего контейнера.

### Проверка релиза

Пройдены Go- и browser-тесты, ESLint, production-сборка интерфейса и проверка
ARM64-образа. На изолированном MikroTik CHR проверены обновление с 1.6.19,
RouterOS-скрипты, маршрутизация, DNS, обязательные правила сервисов, подавление
переключений при деградации WAN и восстановление после полной остановки
контейнера.

## English

### Overview

Version 1.6.20 closes two configuration-recovery gaps. A clean installation
recovers when its first Apply is interrupted, and manual rollback follows the
same concurrency rules as a normal Apply.

### Changes

- Before the first Apply, the system stores a separate safe recovery
  generation. If the process exits before creating `active.json`, the next
  start restores runtime and RouterOS, verifies the result, and permits another
  Apply. The unverified candidate never becomes active.
- Manual rollback uses the shared mutation barrier. It cannot start during a
  container update, probation, recovery, subscription activation, or another
  unfinished Apply, and it cannot overwrite another operation journal.
- Updating from 1.6.19 preserves the active configuration, secrets, node
  quality history, and user settings.

### Installation and update

For a clean installation, use `sb-gateway-1.6.20-routeros-bundle.zip` and the
[installation guide](../INSTALL.md).

To update an existing installation, upload
`sb-gateway-1.6.20-linux-arm64.tar` under
**Operations → Container update**. The panel checks architecture, version, and
SHA-256 before stopping the current container.

### Release verification

Go and browser tests, ESLint, the production UI build, and ARM64 image
validation passed. An isolated MikroTik CHR verified the update from 1.6.19,
RouterOS scripts, routing, DNS, mandatory service rules, WAN degradation
suppression, and recovery from a full container outage.
