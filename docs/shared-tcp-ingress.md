# Общий TCP-порт для входящих подключений

## Несколько CDN

WS, gRPC, HTTPUpgrade, XHTTP и HTTPS-подписка могут использовать один origin
TCP-порт с разными origin-доменами и разными CIDR провайдеров. Это не требует
включать общий порт Reality. Публичный порт CDN, видимый клиенту, и origin-порт
по-прежнему задаются отдельно.

RouterOS пропускает объединение разрешений на общий сокет. Nginx дополнительно
проверяет исходный IP для конкретного origin-домена, если на порту смешаны
разные ограничения. Cloudflare IP не даёт доступ к Gcore virtual host и наоборот.
HTTP Host не может переключить запрос в другой origin после выбора TLS SNI:
несовпадение возвращает 421. CDN должен передавать настроенный origin SNI.
Одинаковый origin-домен и порт с разными CIDR или TLS-профилями отклоняется:
для независимых границ используйте разные origin-домены.

Secret-header и ручные IPv4 CIDR сохранены. CIDR не удостоверяет аккаунт CDN
и не является mTLS. Прямой endpoint на общем порту не отменяет защиту соседнего
CDN-домена. Management-панель в этот механизм не включается: TCP 8080, 9080,
9443, 11001–11004 и 19080–19083 зарезервированы для внутренних сервисов.

## Reality + HTTPS на 443

**Настройки → Входящие подключения → Общий TCP 443 для Reality и HTTPS**.
Поле конфигурации: `public_exposure.shared_tcp_443`, по умолчанию `false`;
отсутствующее поле тоже означает выключенный режим.

Переключатель разрешает общий порт, но не меняет заданные порты:
у нужного Reality-транспорта задайте входящий TCP 443, у CDN — origin TCP 443.
При выключении сначала разведите конфликтующие подключения по разным портам.

При включении Nginx stream читает ClientHello без TLS termination и выбирает:

| Вход | Внутренний адрес |
|---|---|
| HTTPS/CDN | `127.0.0.1:16443` |
| Reality | `127.0.0.1:16444` |
| gRPC + Reality | `127.0.0.1:16445` |
| XHTTP + Reality | `127.0.0.1:16446` |
| Неизвестный/отсутствующий SNI | Закрытие соединения через `127.0.0.1:16447` |

Основной и дополнительные Reality SNI должны однозначно определять транспорт;
совпадение с другим Reality или HTTPS origin отклоняется. Скрытый/нечитаемый
SNI не маршрутизируется. Индивидуальная привязка Reality к WAN IP при общем
443 запрещена: после NAT нельзя достоверно восстановить прежнюю границу.
Для такого подключения оставьте отдельный порт.

Внутренние порты резервируются только при включённой опции, слушают loopback
и не публикуются RouterOS. PROXY protocol передаёт исходный IP; HTTPS доверяет
ему только от loopback-прокси, Xray принимает его на loopback-inbound.
Клиентские и reverse-профили сохраняют внешний порт 443 — внутренние порты
в экспорте не используются. Hysteria 2 UDP 443 остаётся независимым.
Порты Reality, отличные от 443, по-прежнему идут напрямую в Xray.

## Обновление и восстановление

- Требуется новый образ контейнера с `nginx-mod-stream`, не только замена
  runtime-файлов старого образа. Тестовые правила в образ не добавляются.
- Перед расширением правил RouterOS сначала вооружается его rollback guard,
  затем принимается runtime с доменными ограничениями и лишь затем меняется NAT.
  При ошибке RouterOS откатывается раньше, чем снимаются новые runtime-ограничения.
- При передаче 443 от Xray к Nginx первым перезапускается Xray; при обратной
  передаче — Nginx. Включение/выключение режима через Apply может прервать
  соединения затронутых процессов: это не бесшовная миграция сокета.
- Проверенные CIDR для Nginx хранятся в `/state/control-plane/cdn-origin/`;
  переопределение пути — `SB_ORIGIN_CIDR_ROOT`. Пустые начальные файлы запрещают
  доступ. Первый Apply требует успешного feed или проверенного LKG.
- При смешанных границах Cloudflare также обновляется control plane каждые
  15 минут, в отдельном `SB_CDN_CLOUDFLARE_V4`. Старый ежедневный updater и
  `SB_CLOUDFLARE_V4` сохраняются для несмешанных Cloudflare-портов.
- После подтверждения адресов RouterOS записывается CIDR-файл, выполняются
  `nginx -t`, graceful reload и проверка процесса. Неизменившийся файл не вызывает
  reload. Ошибка возвращает предыдущий файл; попытка восстановить Nginx имеет
  отдельный ограниченный контекст. Новый feed не отмечается успешным при ошибке.
- CIDR — оперативное состояние: откат конфигурации не восстанавливает старые
  отозванные сети. Graceful reload не перезапускает Xray; установленные потоки
  могут продолжать обслуживаться прежним worker. Это не мгновенный отзыв уже
  установленных соединений. Сбои одного provider не блокируют другие feeds.

## Проверка

Профильные Go-тесты покрывают конфликты SNI, резервирование портов, отдельные
слушатели, PROXY settings всех трёх Reality-транспортов, восстановление CIDR,
порядок рестартов и pre-apply guard. UI: TypeScript, Node contract tests,
изолированный React fixture из production Toggle/JSX/CSS на 1440 и 390 px,
переключение с клавиатуры и отсутствие горизонтального переполнения.

`SB_SHARED_LIVE_NGINX=1 go test ./internal/runtimeconfig -run
TestSharedIngressLiveNginx -v` запускается только в изолированном Linux-контейнере
с Nginx + stream. Проверяет реальные TLS/SNI, положительные/отрицательные CIDR,
подмену Host, неизвестный SNI, передачу исходного IP, обновление ограничений
и сохранение открытого Upgrade-потока после reload. Reality-бэкенд в этом тесте —
TLS-стенд, не полноценная VLESS-сессия. Общий Linux-прогон `go test ./cmd/...
./internal/... ./routeros/...` и `go vet` прошли 2026-09-08; также прошли 17
связанных Node-тестов и TypeScript. Windows-прогоны имели нестабильные ошибки
очистки временных файлов в неизменённых lifecycle/storage тестах.

Нужны отдельные испытания на hAP ax³: реальные Reality/gRPC/XHTTP клиенты и
reverse-узлы, скорость/CPU/память, переключение режима через Apply и длительные
сессии. Эти результаты не подменяются локальным тестом Nginx.
